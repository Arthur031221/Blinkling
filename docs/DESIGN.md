# Design and integration

## Floating window

Google Meet keeps meeting controls in a movable, resizable picture in picture window while another tab or app is in use. Its controls return to the meeting or end the call. Closing that window returns to the meeting. Eligible conferencing pages can request automatic opening after a tab switch. See [Meet window controls](https://support.google.com/meet/answer/13665919?hl=en) and [presenting in Meet](https://support.google.com/meet/answer/9308856?hl=en).

Glimpselet uses [Document Picture in Picture](https://developer.chrome.com/docs/web-platform/document-picture-in-picture). The toolbar or Open shortcut opens the companion page. **Float** is its first action. A fresh click is required to open the floating window. Chrome limits [automatic opening](https://developer.chrome.com/blog/automatic-picture-in-picture) to eligible conferencing pages, so Glimpselet offers one prominent click. The browser owns position and may reuse it. Glimpselet remembers observed dimensions and offers compact and expanded states. The opener must stay open. Closing the bubble stops sharing.

Screen sharing starts inside the bubble. The browser picker chooses a tab, window or screen, including native apps. Guides and translation use the DOM of an accessible web page. Native apps have pixels only.

## Full screen and Shift crop

Crop freezes shared video at its native resolution. The bubble contents fade out, a fresh video frame is awaited, and the frozen image fills the opener window. The selector uses `requestFullscreen()` when gesture activation is available. An extension command can instead focus the opener and temporarily set its browser window to fullscreen. The previous window state is restored on completion or cancellation.

The selector dims the outside, shows pixel dimensions and has eight resize handles. Enter confirms. Esc cancels. Arrow keys create or move a rectangle, Shift moves ten pixels, and Ctrl or Command with arrows resizes it. Pointer coordinates map back to native frame pixels, including display scaling. The crop appears in the bubble. On a web page the same selector overlays the live page.

The frozen selector keeps the native frame. Finished crops, web captures, shared frames, PDF pages and attachments use one PNG encoder that preserves images within the transport budget. Images are resampled from the original pixels until their data URL fits the shared five million character limit, neither side exceeds 8000 pixels and the image fits the bridge decoder limit of 40 million pixels. The dimension cap follows the [provider image limits](https://platform.claude.com/docs/en/build-with-claude/vision). Both the local bridge and direct API receive the same bounded image.

Holding Shift for 200 ms enters crop mode unless focus is in an editable control. Releasing early or pressing another key cancels the hold, preserving Shift+Tab and ordinary typing. This shortcut can be disabled. Bubble contents become 25 percent opaque during selection. Document PiP exposes no native window opacity or click through API, so its browser frame cannot become transparent or pass pointer events to another app. Move the bubble away on systems whose screen capture includes that frame.

The dedicated trial browser enables Chromium's experimental `ExcludePipFromScreenCapture` feature. Chromium currently disables it by default. Support depends on the browser build and capture source. This can omit the native PiP window from capture, but does not make it transparent on screen. A regular installed browser keeps its own settings. See the [Chromium feature declaration](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/media/capture/capture_switches.cc) and [capture exclusion implementation](https://chromium.googlesource.com/chromium/src/+/d6870cd14078040dc0cba81d9c9780577ff00a58).

Chrome [commands](https://developer.chrome.com/docs/extensions/reference/api/commands) restrict default global shortcuts to Ctrl+Shift plus a digit. The browser crop command uses Ctrl+Shift+S, or Command+Shift+S on macOS. The global command defaults to Ctrl+Shift+7, or Command+Shift+7 on macOS, and can be remapped at `chrome://extensions/shortcuts`. The digit 7 avoids the [macOS Screenshot shortcuts](https://support.apple.com/en-au/102646), including Command+Shift+5. A page alone cannot hear Shift in another app.

## The running Claude Code conversation

The chosen integration is a documented [Claude Code channel](https://code.claude.com/docs/en/channels), which pushes messages into a running interactive session. The MCP server declares `experimental: {"claude/channel": {}}` and sends `notifications/claude/channel`. A nonce delivered through the channel must be returned by the session before live mode is offered. Ordinary MCP connectivity cannot be mistaken for live delivery. The [channel reference](https://code.claude.com/docs/en/channels-reference) documents notifications and reply tools.

Custom channels are a research preview. After installing the plugin, restart the desired conversation with its actual UUID:

```sh
claude --resume SESSION_ID --dangerously-load-development-channels plugin:glimpselet@glimpselet
```

Accept the channel warning yourself. Authentication and organization policy must allow channels. The bubble selects live mode when its readiness check succeeds. Questions enter that interactive conversation. Images are fetched through `glimpse_channel_context`. The session returns scoped chunks through `glimpse_channel_reply`, with `done=true` on its final chunk. Those chunks stream into the bubble. The terminal's existing model, permissions and tools apply. Bubble model and effort controls are disabled for live requests.

Only replies to bubble requests are mirrored. Ordinary terminal turns are not copied. Stopping the bubble stops waiting and rejects late chunks. It cannot send Esc to the terminal. Its status says to stop the terminal separately if it is still working.

## Parallel continuation and alternatives

When a live channel is unavailable, recent conversations for the current project are listed through the [Agent SDK](https://platform.claude.com/docs/en/agent-sdk/sessions). The bridge passes the exact selected UUID to `claude --resume ID -p`, without forking. The bubble labels this a **parallel continuation**. It writes to that conversation but does not inject into its open terminal. Avoid simultaneous requests against the same transcript. A dedicated thread starts with a new `--session-id` and resumes it for follow ups. See the [CLI reference](https://code.claude.com/docs/en/cli-reference) and [print mode](https://code.claude.com/docs/en/headless).

[Remote Control](https://code.claude.com/docs/en/remote-control) provides first party web and mobile access. Its documentation does not expose a third party embedding API. We use channels rather than reverse engineering that service.

We checked [hooks](https://code.claude.com/docs/en/hooks): SessionStart, Stop and message events report lifecycle or output information, and hook inputs include `session_id` and `transcript_path`. Hooks do not provide an independent arbitrary input channel. Claude Code owns its JSONL session files. Glimpselet lists sessions through the SDK and never edits transcripts or watches every terminal message. Scoped MCP replies avoid copying unrelated terminal content.

For local development with `--plugin-dir`, the plugin identity is `glimpselet@inline`. Claude Code 2.1.296 may display an installed plugin warning for this session only identity. Its MCP tools and channel still load. The equivalent development server selector is `server:plugin:glimpselet:glimpselet`. We confirm actual delivery through the nonce handshake rather than trusting this startup message. The `/glimpse` command authorizes connection probes and scoped bubble replies while preserving ordinary tool permissions.

Before retrying an interrupted first answer, the bridge checks the exact UUID through the SDK conversation history API. A saved user message makes that same conversation resumable, even without a completed reply or summary. The request stays reserved during this check, and cancellation prevents the child from starting. If no conversation message exists, creation keeps the original UUID. An initialization file that blocks creation produces a clear instruction to choose a new conversation. Glimpselet never deletes an ambiguous transcript.

Child continuations remove inherited parent session identity flags. These flags can disable transcript saving in a worker process, which would break follow ups. An explicitly selected or dedicated Glimpselet conversation keeps its own UUID.

## API effort and guide budgets

Both API paths send the selected effort through `output_config.effort`, as described in the [Messages API effort documentation](https://platform.claude.com/docs/en/build-with-claude/effort). Requests that omit effort keep their existing provider default.

Guide prompts share the chat question limit of 8,000 characters. Compact element tuples preserve all 120 stable IDs on normal pages. The builder measures serialized JSON, including escaped labels, and reduces label length to fit. If IDs and roles alone exceed the budget, it removes complete trailing entries. It never cuts a JSON record in half.

## Pairing, page access and privacy

The bridge binds to loopback. Pairing uses a ten minute, one use code and an origin bound token lasting twelve hours. An SSH local forward supports a remote Claude Code host. In tunnel mode, the welcome guide offers the extension release ZIP and instructs the browser user to extract it and load the extracted folder on their own computer. It does not show the remote host's extension path or offer zero-install launch. Direct mode keeps the stable local extension path, while a configured browser store link takes precedence over either unpacked flow. Direct API mode uses the user's Anthropic key instead. The bubble names its connection mode.

Re-pairing keeps the current connection until the new bridge authenticates. The client then adopts that authenticated socket and retires the old requests and reconnect timer. Delayed events from the retired socket cannot change the new identity or interrupt its answers. A failed handshake leaves the previous project and reconnect destination intact. Credential writes are ordered, so a later pairing remains the saved connection. Startup loading initializes credentials only once. Delayed reads are discarded after an accepted pairing or shutdown, and loading cannot restart after initialization while a new credential write is still pending. The server also checks client ownership before processing messages or cancelling work on close. Replacing a client aborts its old job and keeps new work blocked until that job finishes cleanup. Conversation selection belongs to one client and one request. Clearing the conversation cancels a pending selection and releases its lock. Delayed lookup results cannot restore an earlier thread or release a newer selection's lock. A panel replaced by another window stops automatic reconnect after the ownership close code, so both panels cannot repeatedly interrupt each other's answers. Ordinary connection loss still reconnects, and explicit pairing remains available.

Web access starts with `activeTab`. Persistent site access is optional and requested when needed. Chrome's capture API also requires an activeTab grant or all sites permission. Protected pages cannot be injected. Page context omits private and editable fields, treats page text as untrusted input, and validates returned element and translation IDs. PDF.js and its worker, fonts and character maps are bundled. PDFs use this reader because Chrome's built in viewer cannot be scripted.

Automatic page context follows semantic changes at the same URL, including the displayed PDF page. A bounded revision includes safe text, labels, title and the password page gate. Geometry, generated element IDs, private text and overlay animations do not cause duplicate requests. Changes invalidate stale questions and queue behind a foreground answer, translation or composed draft. Clearing or sending the draft lets the queued refresh run. Automatic reader messages are accepted only from the current source tab. A background PDF completing its render cannot select itself or redirect automatic requests. Explicit reader actions can select their document.

Passive mode is opt in, debounced and capped at six requests per minute. Stable perceptual changes in shared video can trigger summaries. Detected password pages and blocklisted hosts are excluded. One shared privacy guard checks password types and autocomplete metadata in the document, open shadow roots and accessible frame or object documents. Loading or inaccessible embedded documents pause web reading and capture. A 650 ms timer checks nested privacy changes. Context collection and automatic transmission also perform fresh checks. Crops recheck after selection and decoding, and full page capture checks each frame and the final image. These checks discard captures when a password field appears during the operation. The guard reads attributes without reading input values and fails closed when its inspection budget is exhausted. Closed shadow roots and native app password fields cannot be inspected. The preceding hour's reported or estimated cost is shown. Captures and bubble chat stay in memory. Preferences and credentials have separate documented scopes. See [security and storage](SECURITY.md).

Translation stores each original with the last value Glimpselet wrote. Apply and restore check that the current text still matches, so site updates survive delayed replies and returning to the original. Collecting changed text replaces the original and rotates its response ID. Restoration also invalidates old IDs. Nodes that become private are skipped. Restoration checks privacy separately from visibility, so collapsed paragraphs and blank translations can still return to their saved originals.

Translation replies use the same validator in tests and production. Each returned ID must belong to the requested batch, and duplicate IDs are ignored. Blank replies are rejected. Accepted text is preserved in full. Replies above 12,000 characters per node or eight times the source length, with a minimum allowance of 1,000 characters, are rejected rather than shortened. Each batch must return and apply every requested node. A failed later batch restores the earlier changes while preserving intervening site edits. Source nodes above 3,500 characters produce an explicit error before any text changes. Collection allows 20 reads, each bounded to 160 nodes and 24,000 characters. If text remains after the last read or the cursor fails to advance, translation reports an error before any text changes. The user can select a shorter passage instead.
