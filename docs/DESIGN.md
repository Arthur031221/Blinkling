# Design and integration

## Floating window

Google Meet keeps meeting controls in a movable, resizable picture in picture window while another tab or app is in use. Its controls return to the meeting or end the call. Closing that window returns to the meeting. Eligible conferencing pages can request automatic opening after a tab switch. See [Meet window controls](https://support.google.com/meet/answer/13665919?hl=en) and [presenting in Meet](https://support.google.com/meet/answer/9308856?hl=en).

Glimpselet uses [Document Picture in Picture](https://developer.chrome.com/docs/web-platform/document-picture-in-picture). The toolbar or Open shortcut opens the companion page. **Float** is its first action. A fresh click is required to open the floating window. Chrome limits [automatic opening](https://developer.chrome.com/blog/automatic-picture-in-picture) to eligible conferencing pages, so Glimpselet offers one prominent click. The browser owns position and may reuse it. Glimpselet remembers observed dimensions and offers compact and expanded states. The opener must stay open. Closing the bubble stops sharing.

Screen sharing starts inside the bubble. The browser picker chooses a tab, window or screen, including native apps. Guides and translation use the DOM of an accessible web page. Native apps have pixels only.

## Full screen and Shift crop

Crop freezes shared video at its native resolution. The bubble contents fade out and a fresh video frame is awaited. The opener shows one captured pixel per physical display pixel, using its device pixel ratio. A larger frame can be scrolled in both directions, with Shift and the wheel for horizontal movement. The selection remains attached to the same captured pixels while scrolling. Moving to a display with a different pixel ratio cancels the selection so its scale stays accurate. The selector uses `requestFullscreen()` when gesture activation is available. An extension command can instead focus the opener and temporarily set its browser window to fullscreen. The previous window state is restored on completion or cancellation.

The selector dims the outside, shows pixel dimensions and has eight resize handles. Enter confirms. Esc cancels. Arrow keys create or move a rectangle, Shift moves ten pixels, and Ctrl or Command with arrows resizes it. Pointer coordinates map back to native frame pixels, including display scaling. The crop appears in the bubble. On a web page the same selector overlays the live page.

The frozen selector keeps the native frame. Finished crops, web captures, shared frames, PDF pages and attachments use one PNG encoder that preserves images within the transport budget. Images are resampled from the original pixels until their data URL fits the shared five million character limit, neither side exceeds 8000 pixels and the image fits the bridge decoder limit of 40 million pixels. The dimension cap follows the [provider image limits](https://platform.claude.com/docs/en/build-with-claude/vision). Both the local bridge and direct API receive the same bounded image.

Holding Shift for 200 ms enters crop mode unless focus is in an editable control. Releasing early or pressing another key cancels the hold, preserving Shift+Tab and ordinary typing. This shortcut can be disabled. Bubble contents become 25 percent opaque during selection. Document PiP exposes no native window opacity or click through API, so its browser frame cannot become transparent or pass pointer events to another app. Move the bubble away on systems whose screen capture includes that frame.

The dedicated trial browser enables Chromium's experimental `ExcludePipFromScreenCapture` feature. Chromium currently disables it by default. Support depends on the browser build and capture source. This can omit the native PiP window from capture, but does not make it transparent on screen. A regular installed browser keeps its own settings. See the [Chromium feature declaration](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/media/capture/capture_switches.cc) and [capture exclusion implementation](https://chromium.googlesource.com/chromium/src/+/d6870cd14078040dc0cba81d9c9780577ff00a58).

Chrome [commands](https://developer.chrome.com/docs/extensions/reference/api/commands) restrict default global shortcuts to Ctrl+Shift plus a digit. The browser crop command uses Ctrl+Shift+S, or Command+Shift+S on macOS. The global command defaults to Ctrl+Shift+7, or Command+Shift+7 on macOS, and can be remapped at `chrome://extensions/shortcuts`. The digit 7 avoids the [macOS Screenshot shortcuts](https://support.apple.com/en-au/102646), including Command+Shift+5. A page alone cannot hear Shift in another app.

## The running Claude Code conversation

The chosen integration is a documented [Claude Code channel](https://code.claude.com/docs/en/channels), which pushes messages into a running interactive session. The MCP server declares `experimental: {"claude/channel": {}}` and sends `notifications/claude/channel`. A nonce delivered through the channel must be returned by the session before live mode is offered. Ordinary MCP connectivity cannot be mistaken for live delivery. The [channel reference](https://code.claude.com/docs/en/channels-reference) documents notifications and reply tools.

Custom channels are a research preview and must be enabled when starting an interactive session. The flag cannot be added to a session that is already running, and print mode ignores channel flags. Glimpselet is a custom development channel, so the current allowlist requires `--dangerously-load-development-channels`; authentication and organization policy can still prevent it. No permission bypass is used. Glimpselet detects readiness automatically and falls back to the latest saved session of the current project when there is no verified live channel. The welcome page and bubble use one connection label in every mode, **已連到你的 Claude Code** in Traditional Chinese.

The ordinary restart shortcut is `claude --continue --dangerously-load-development-channels plugin:glimpselet@glimpselet` from the same project directory after exiting Claude Code. The installer returns this optional hint once per bridge when its channel is unavailable. For a source checkout, keep `--plugin-dir` and use the development server selector below. To identify a specific existing conversation before restarting it, the documented [session naming and resume procedure](https://code.claude.com/docs/en/sessions#name-your-sessions) avoids guessing its UUID:

1. In the terminal conversation you want to connect, wait for its current answer to finish. Run `/rename glimpselet-reading`, using a unique name if that name is already used. To get its exact UUID instead, run [`/status`](https://code.claude.com/docs/en/commands), copy the **Session ID** row: it is the conversation's UUID. Press Esc to return. We verified this row in Claude Code 2.1.296.
2. Run `/exit` and wait until the shell prompt returns. For an attached background conversation, use `/stop` instead: `/exit` only detaches from it. Keep only one owner of this conversation. Do not keep two interactive terminals or processes writing to it; their messages can interleave.
3. In the same project directory on the same host, run the command below. If you chose another name, replace `glimpselet-reading` with it. For SSH, run this on the remote host where Claude Code and the conversation live. A known UUID also works in place of the quoted name.

These discovery and resume steps follow the [session guide](https://code.claude.com/docs/en/sessions) and [built-in commands](https://code.claude.com/docs/en/commands).

```sh
claude --resume "glimpselet-reading" --dangerously-load-development-channels plugin:glimpselet@glimpselet
```

For a source checkout loaded with `--plugin-dir`, pass that flag again when resuming; it is not saved with the conversation. Replace the absolute path below with your Glimpselet checkout. Run it from the original conversation's project directory, which can differ from the plugin checkout:

```sh
claude --plugin-dir "/absolute/path/to/Glimpselet" --resume "glimpselet-reading" --dangerously-load-development-channels server:plugin:glimpselet:glimpselet
```

If the original terminal has already closed, run `claude --resume` from the project directory. Search the picker and press Space to preview the messages; Ctrl+A includes other projects on this host. Resume the matching conversation, then follow steps 1–3. A known session UUID also works in place of the quoted name. An ambiguous name opens the picker instead of resuming directly.

After reopening, check `/status` still shows the same Session ID and that an earlier message is present before running `/glimpselet:glimpse`.

After either startup command, accept the channel warning and any MCP server consent prompt yourself. Run `/mcp` and check that `plugin:glimpselet:glimpselet` is connected. If it is disabled or failed, enable or reconnect it there before opening the bubble. Authentication and organization policy must allow channels; a connected MCP server alone does not prove that channel messages can arrive.

Run `/glimpselet:glimpse` in that resumed terminal; the welcome guide connects the browser automatically. Keep the terminal visible during the first connection: if Claude Code asks for permission to answer the readiness probe with `glimpse_channel_ready`, approve that call. Approve the scoped context and reply calls when prompted for the first bubble question too. These prompts use your session's normal tool permissions; the slash command does not bypass them. A pending prompt pauses delivery until you answer it. See the [channel permission guidance](https://code.claude.com/docs/en/channels#push-a-message-in).

The bubble selects live mode only when its nonce readiness check succeeds. Questions enter that interactive conversation. Images are fetched through `glimpse_channel_context`. The session returns scoped chunks through `glimpse_channel_reply`, with `done=true` on its final chunk. Those chunks stream into the bubble. The terminal's existing model, permissions and tools apply. Bubble model and effort controls are disabled for live requests.

Only replies to bubble requests are mirrored. Ordinary terminal turns are not copied. Stopping the bubble stops waiting and rejects late chunks. It cannot send Esc to the terminal. Its status says to stop the terminal separately if it is still working.

## Parallel continuation and alternatives

When a live channel is unavailable, recent conversations for the current project are listed through the [Agent SDK](https://platform.claude.com/docs/en/agent-sdk/sessions). For the first conversational request, the bridge automatically selects the most recently modified saved session, with `includeWorktrees: false` and the current project directory. It passes that exact UUID to `claude --resume ID -p`, without forking, and anchors later requests to it. A project with no saved session gets a new thread. Explicit choices in the conversation picker override automatic selection. This is a parallel continuation. It writes to that conversation but does not inject into its open terminal. Avoid simultaneous requests against the same transcript. A dedicated thread starts with a new `--session-id` and resumes it for follow ups. See the [CLI reference](https://code.claude.com/docs/en/cli-reference) and [print mode](https://code.claude.com/docs/en/headless).

[Remote Control](https://code.claude.com/docs/en/remote-control) provides first party web and mobile access. Its documentation does not expose a third party embedding API. We use channels rather than reverse engineering that service.

We checked [hooks](https://code.claude.com/docs/en/hooks): SessionStart, Stop and message events report lifecycle or output information, and hook inputs include `session_id` and `transcript_path`. Hooks do not provide an independent arbitrary input channel. Claude Code owns its JSONL session files. Glimpselet lists sessions through the SDK and never edits transcripts or watches every terminal message. Scoped MCP replies avoid copying unrelated terminal content.

For local development with `--plugin-dir`, the plugin identity is `glimpselet@inline`. Claude Code 2.1.296 may display an installed plugin warning for this session only identity. Use the development server selector `server:plugin:glimpselet:glimpselet`, check the actual server in `/mcp`, and complete its consent prompts. We confirm actual delivery through the nonce handshake rather than trusting a startup message. The `/glimpselet:glimpse` command instructs Claude to handle connection probes and scoped bubble replies while preserving ordinary tool permissions.

Before retrying an interrupted first answer, the bridge checks the exact UUID through the SDK conversation history API. A saved user message makes that same conversation resumable, even without a completed reply or summary. The request stays reserved during this check, and cancellation prevents the child from starting. If no conversation message exists, creation keeps the original UUID. An initialization file that blocks creation produces a clear instruction to choose a new conversation. Glimpselet never deletes an ambiguous transcript.

Child continuations remove inherited parent session identity flags. These flags can disable transcript saving in a worker process, which would break follow ups. An explicitly selected or dedicated Glimpselet conversation keeps its own UUID.

## API effort and guide budgets

Both API paths send the selected effort through `output_config.effort`, as described in the [Messages API effort documentation](https://platform.claude.com/docs/en/build-with-claude/effort). Requests that omit effort keep their existing provider default.

Guide prompts share the chat question limit of 8,000 characters. Compact element tuples preserve all 120 stable IDs on normal pages. The builder measures serialized JSON, including escaped labels, and reduces label length to fit. If IDs and roles alone exceed the budget, it removes complete trailing entries. It never cuts a JSON record in half.

## Marketplace upgrades

An existing marketplace cache and an installed plugin are separate. Repeating Install can leave the installed v1 plugin in place. Refresh with `claude plugin marketplace update glimpselet`, then run `claude plugin update glimpselet@glimpselet`. Restart Claude Code or use `/reload-plugins` to load the updated plugin. Verify `claude plugin list` reports **2.0.0** before invoking `/glimpselet:glimpse`. These commands follow the [Claude Code plugin update documentation](https://code.claude.com/docs/en/discover-plugins) and [marketplace refresh documentation](https://code.claude.com/docs/en/plugin-marketplaces).

We verified both a fresh install and a cached v1.1.1 upgrade with Claude Code 2.1.296 in isolated configuration directories against staged Git marketplace artifacts. Both installed plugin and extension 2.0.0; the installed command's `panel_open` tool opened the welcome guide and paired with the packaged extension in Chromium. The cached-v1 fixture came from commit `a27fd993`. This verifies the staged artifacts. A later authorized release must separately verify the public marketplace commit, packaged launcher and extension, and installed welcome/pairing flow before declaring publication complete.

The welcome guide refreshes the stable visible local extension folder. Existing cards loaded from `~/.glimpselet/extension` or another source folder need a one-time removal and load from `~/Glimpselet-extension`; Chrome cannot move a card’s source path on Reload. A browser that already loaded it must reload the extension and verify version 2.0.0. For SSH, download the updated ZIP on the browser computer, extract it into the previously loaded folder, and reload there. The remote host cannot launch a zero-install browser on the user's computer.

## Pairing, page access and privacy

The bridge binds to loopback. Pairing uses a ten minute, one use code and an origin bound token lasting twelve hours. An SSH local forward supports a remote Claude Code host. In tunnel mode, the welcome guide offers the extension release ZIP and instructs the browser user to extract it and load the extracted folder on their own computer. It does not show the remote host's extension path or offer zero-install launch. Direct mode keeps the stable local extension path, while a configured browser store link takes precedence over either unpacked flow. Direct API mode uses the user's Anthropic key instead. The bubble shows only the connection label, without a mode, bridge port, project path or session UUID in its footer.

Re-pairing keeps the current connection until the new bridge authenticates. The client then adopts that authenticated socket and retires the old requests and reconnect timer. Delayed events from the retired socket cannot change the new identity or interrupt its answers. A failed handshake leaves the previous project and reconnect destination intact. Credential writes are ordered, so a later pairing remains the saved connection. Startup loading initializes credentials once; a service-worker connection update can refresh an existing bubble after a new automatic handshake. Unchanged credentials leave its socket and pending work intact. Delayed reads are discarded after an accepted pairing or shutdown, and loading cannot restart after initialization while a new credential write is still pending. The server also checks client ownership before processing messages or cancelling work on close. Replacing a client aborts its old job and keeps new work blocked until that job finishes cleanup. Conversation selection belongs to one client and one request. Clearing the conversation cancels a pending selection and releases its lock. Delayed lookup results cannot restore an earlier thread or release a newer selection's lock. A panel replaced by another window stops automatic reconnect after the ownership close code, so both panels cannot repeatedly interrupt each other's answers. Ordinary connection loss still reconnects. Running `/glimpselet:glimpse` again opens a fresh welcome page to reconnect automatically.

Web access starts with `activeTab`. Persistent site access is optional and requested when needed. Chrome's capture API also requires an activeTab grant or all sites permission. Protected pages cannot be injected. Page context omits private and editable fields, treats page text as untrusted input, and validates returned element and translation IDs. Accepted selections retain their full text for Explain, Translate and Ask. PDF.js and its worker, fonts and character maps are bundled. PDFs use this reader because Chrome's built in viewer cannot be scripted. A PDF URL loads automatically only when its origin already has permission. For a new origin, the reader keeps the URL ready and requests permission when the user clicks Open URL. Screen sharing works in direct API mode without a paired bridge.

Automatic page context follows semantic changes at the same URL, including the displayed PDF page. A bounded revision includes safe text, labels, title and the password page gate. Geometry, generated element IDs, private text and overlay animations do not cause duplicate requests. Changes invalidate stale questions and queue behind a foreground answer, translation or composed draft. Clearing or sending the draft lets the queued refresh run. Automatic reader messages are accepted only from the current source tab. A background PDF completing its render cannot select itself or redirect automatic requests. Explicit reader actions can select their document.

Passive mode is opt in, debounced and capped at six requests per minute. Stable perceptual changes can trigger summaries only for an inspectable HTTP or HTTPS browser tab whose Chrome Capture Handle matches the checked tab. The native floating window is recognized by its panel opener and Chrome alwaysOnTop flag, so ordinary blank tabs still become page sources. Before sharing, an existing site grant permits a main world script to expose a random handle only to this extension. The video track must report a browser surface, the same handle and origin, and a live, unmuted track both before freezing and after inspection. The initial injection records the top frame document id and URL. Privacy inspection targets that exact document. Capture handle changes, mute and end events invalidate pending samples and reset the change detector. The native picker starts directly from the click while source preparation runs in parallel. Unknown surfaces, another tab, native windows, monitors, missing handles and unsupported page schemes withhold automatic frames. Manual screen capture remains available. [Chrome documents this source identity mechanism](https://developer.chrome.com/docs/web-platform/capture-handle). The screen sampler freezes a candidate frame before checking its page. Tab and window events invalidate the source immediately, and delayed lookups cannot restore an older source. Transmission rechecks the source, stream and revision and sends only that frozen frame. Detected password pages and blocklisted hosts are excluded. One shared privacy guard checks password types and autocomplete metadata in the document, open shadow roots and accessible frame or object documents. Loading or inaccessible embedded documents pause web reading and capture. A 650 ms timer checks nested privacy changes. Context collection and automatic transmission also perform fresh checks. Crops recheck after selection and decoding, and full page capture checks each frame and the final image. These checks discard captures when a password field appears during the operation. The guard reads attributes without reading input values and fails closed when its inspection budget is exhausted. Closed shadow roots and native app password fields cannot be inspected. The preceding hour's reported or estimated cost is shown. Captures and bubble chat stay in memory. Preferences and credentials have separate documented scopes. See [security and storage](SECURITY.md).

Translation stores each original with the last value Glimpselet wrote. Apply and restore check that the current text still matches, so site updates survive delayed replies and returning to the original. Collecting changed text replaces the original and rotates its response ID. Restoration also invalidates old IDs. Nodes that become private are skipped. Restoration checks privacy separately from visibility, so collapsed paragraphs and blank translations can still return to their saved originals.

Translation replies use the same validator in tests and production. Each returned ID must belong to the requested batch, and duplicate IDs are ignored. Blank replies are rejected. Accepted text is preserved in full. Replies above 12,000 characters per node or eight times the source length, with a minimum allowance of 1,000 characters, are rejected rather than shortened. Each batch must return and apply every requested node. A failed later batch restores the earlier changes while preserving intervening site edits. Source nodes above 3,500 characters produce an explicit error before any text changes. Collection allows 20 reads, each bounded to 160 nodes and 24,000 characters. If text remains after the last read or the cursor fails to advance, translation reports an error before any text changes. The user can select a shorter passage instead.

## Document identity and capture timing

Every injected page document gets a random identity that survives reinjection and changes on reload. Guide and translation replies carry that identity and the original URL back to the content script. The receiver rejects replies after navigation, including a reload at the same URL. Restore belongs to the translated document, so switching tabs does not offer another page's originals. Translation obtains page access and injects the current document before collecting text.

A captured web image retains its original page context. Shared screen captures carry pixels without unrelated active tab text. Asking about a live shared screen takes the next frame after hiding the bubble for two paints, then restores its opacity. Frozen crops and web captures remain frozen until replaced. Guide replies are shown as readable steps after their structured response is complete.

The bubble keeps at most 40 chat entries and eight image previews. Up to eight pinned entries survive ordinary history trimming. Reading earlier replies disables automatic scrolling until the user returns to the bottom or sends another question. Image upload is available in Settings, leaving capture controls in the main view.

### Welcome and conversation readiness

The welcome page has exactly three steps: install, connect, and open the bubble. Blink is restored above them. Install offers three browser clicks, a visible `~/Glimpselet-extension` folder with a platform-specific reveal button, and **Try without installing**. Remote installations download a ZIP to a visible folder on the browser computer. The page has no exercises, saved tour progress or replay entry point. Its nine locales match the bubble's supported languages.

The welcome content script detects the extension and the service worker completes the capability handshake automatically. A successful authenticated response is required before the bubble button is enabled. Capability values and ports are kept out of page text. Connection does not open a window. Clicking **Open the bubble** opens the companion page; Chrome requires a fresh click there to create the floating window. The page and extension keep `script-src 'self'`.

A verified live channel is preferred by default, including when readiness arrives after pairing. Without it, the first conversational request resolves the latest session in this project and pins that exact UUID for follow ups. Channel loss falls back to this continuation. A user-selected conversation or a new conversation disables automatic selection for that browser connection. Clear conversation resets the bubble history and creates a new fallback thread. Model and effort controls remain disabled for live requests because the interactive terminal owns them.

Manual page translation reads text nodes from the containing document only. It excludes embedded documents, so unreadable advertising or shopping frames do not prevent this explicit text operation. Detected password fields in the page, open shadow roots or accessible frames still block it. The content script checks again before collecting and applying each batch. Automatic questions, passive summaries and pixel captures retain the stricter check that blocks unreadable embedded content.

The PDF reader's Open chat button focuses or opens the extension chat. Its status explains that Open floating panel in the chat creates the window that stays above other apps. Opening a normal extension window does not prove that a floating window was created.

## Translation on changing pages

A translation response must preserve every supplied text ID. The content script reports actual writes separately from text that disappeared, changed on the site, or became ineligible while the answer was running. The bubble checks that every result is accounted for. It keeps translations on stable nodes and reports skipped text so the user can try again. It never applies an old translation to replacement text. Incomplete model results still stop the operation and restore earlier writes. Restore changes only nodes that retain the extension's last written value, preserving newer site updates.

## Plugin upgrades and release verification

Existing installations need both a marketplace refresh and a plugin update. The supported terminal commands, verified with Claude Code 2.1.296, are:

```sh
claude plugin marketplace update glimpselet
claude plugin update glimpselet@glimpselet
claude plugin list
```

The last command must show `glimpselet@glimpselet` at version **2.0.0** in the intended scope. If several scopes are installed, use the CLI's `--scope user`, `--scope project` or `--scope local` on the update command to select the installation being used. In an already running conversation, run `/reload-plugins` or restart Claude Code before `/glimpselet:glimpse`. The CLI update help says a restart is required; the documented session reload also loads updated plugins. See Anthropic's [plugin update and reload instructions](https://code.claude.com/docs/en/discover-plugins#keep-plugins-updated) and [marketplace commands](https://code.claude.com/docs/en/plugins-reference).

An unpacked extension needs its own reload. Close the old bubble, rerun `/glimpselet:glimpse` to copy the new packaged extension to the stable folder, and reload its card on `chrome://extensions` or `edge://extensions`. On SSH, download the new ZIP through the forwarded welcome guide and replace the extracted files on the browser computer before reloading. The remote host cannot launch the zero-install desktop browser. Verify extension version **2.0.0** on the browser's extensions page and that the command opens `/install` with welcome and pairing, rather than the legacy screen picker.

After `npm run build:plugin`, run `node scripts/plugin-upgrade-test.mjs` to exercise the real CLI in two temporary Claude configuration directories. It stages the reporter's v1.1.1 package from commit `a27fd993`, installs it, refreshes and updates against staged v2 artifacts, and also installs v2 in a fresh profile. It checks the installed manifests, packaged launcher bytes, copied extension and welcome/pairing endpoint through the same `panel_open` tool used by `/glimpselet:glimpse`. It does not edit the account's installed plugins or invoke a model. Browser tests separately check automatic connection, trial isolation, all nine welcome locales and opening the native bubble.

Public release verification remains a separate gate. The reporters' public-main v1.1.1 observation is historical evidence, not a fresh remote check. Staged local v2 passing these checks does not establish public availability. Before an authorized release is declared complete, verify the actual public marketplace commit, its packaged launcher and extension ZIP, and a fresh install and v1 upgrade from that public source. If the public source still installs 1.1.1, keep this gate pending. No manifest-only bump or forced reinstall addresses an unpublished release.
