Blinkling Privacy Policy

Blinkling / Privacy

Last updated: 15 October 2026 · Version 2.1.0

Blinkling has no telemetry. It does not send analytics or diagnostic events to its publisher. This policy explains what the browser helper extension reads, where user data goes, and how it is stored.

Blinkling has no publisher-operated answer service. Blink, the desktop companion, asks the Claude Code you are signed in to on the same computer. The publisher does not receive those requests. Blinkling does not sell user data or use it for advertising.

Information the extension can access

The helper does nothing on its own. When Blink asks about the page you point at, the helper can read the page URL and title, and a bounded list of elements: their role, accessible name, visible text and position. Password and other secure fields are reported as secure, with no text and no value, and input values are never read. For a full-length capture it scrolls the page and takes screenshots of the visible tab. For translation it reads the page text and replaces it in place. For a PDF it fetches the file you chose and shows it in the bundled reader. Images may contain information that cannot be recognized by text filters.

Site access is granted through the browser. The popup offers Allow on all sites, which you can revoke in the browser's extension settings. Without it, the helper only works on a tab where you clicked its toolbar button.

When information is sent

The helper talks only to the Blinkling bridge on 127.0.0.1 of the same computer, through a WebSocket that checks the extension origin and a one-use setup code or a token. It pairs on its own from the local install page. Nothing is sent to a remote server by the extension. The bridge passes what you chose to the Claude Code on that computer, which runs the command-line assistant. Images used by that process are placed in a private temporary directory and removed after the request. The command-line assistant stores persistent conversation transcripts on the host according to its own session behavior.

Auto explain in Blink is optional and starts off. When you turn it on, Blink can send what is on your screen to Claude Code after a large change. Sensitive-content detection is incomplete. Turn it off before showing private content.

Data is used to provide the Blink features you choose. Blinkling's use of information received from browser APIs complies with the Chrome Web Store User Data Policy, including the Limited Use requirements. The publisher does not use page content for unrelated purposes or maintain a browsing-history log. Your questions and captures can contain personal information. Your provider's own data policy applies to processing and retention there.

Storage

Location What is stored
Browser session storage The bridge token and URL. Browser session storage is cleared when the browser session ends. Nothing else is stored by the extension.
Host process memory Temporary pairing state, active requests and connection metadata. It is cleared when the bridge stops.
Host command-line assistant Persistent conversation transcripts stored according to that program's session behavior. Blinkling does not keep these transcripts in browser storage.

Controls

A pick, capture or translation happens only when you ask Blink. Revoke site permissions in the browser's extension settings. Remove the extension to delete its data. Removing the extension does not delete Claude Code transcripts on the host or records retained by your provider. Manage those with the host application or provider account. Usage charges come from your own Claude Code plan; check your provider account for actual charges.

Contact

For privacy questions, contact the maintainer, Arthur031221, through the Blinkling issue tracker. Issues are public. Do not include private page content or credentials.
